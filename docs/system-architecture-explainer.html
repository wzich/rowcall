How Rowcall works.

Rowcall is a local web app wrapped around a Python graph runtime. The browser helps a person edit and inspect one Python document. Python remains the authority for what that document means and how it runs.

The shortest useful model: a launcher starts a browser and a local server; the server reads and safely rewrites one Python file; a Python worker executes its graph and returns bounded previews.

Local-first One active document Python is canonical No database No compute cache Trusted Python execution

No normal-runtime cloud: the browser, server, files, and Python process are local. No database: durable state is the document and its sidecar.
  1. One server process owns one active Python document. There is no document registry or multi-document session.
  2. The Python file owns computation. It contains imports, globals, steps, declared values, and graph edges.
  3. The sidecar owns editor metadata. Position and description do not affect Python execution.
  4. Unsaved browser edits live only in memory. They are a projected document plus a queue of semantic operations.
  5. Python owns language meaning. The browser does not validate or execute an independent graph payload.
  6. Saves are revision-bound. Rowcall refuses to overwrite a file that changed after the browser loaded it.
  7. Runs are revision-bound too. The browser saves first, then runs the exact displayed disk revision.
  8. Each run computes fresh. A selected-step run recomputes every required upstream step.
  9. Nodes get separate namespaces, not separate processes. Some process-wide Python state can still leak.
  10. Only one successful result set stays inspectable. This supports table paging; it is not a compute cache.

02 / SYSTEMS

What each block owns.

Ownership is the easiest way to navigate this repository. Each block below says what belongs there, what does not, and how long its state lives.

01

Launcher & Environment Setup

The public front door. It turns a command and a project path into a running local app or a headless Python command.

Owns: command parsing, project creation, Python selection, environment setup, bundled assets, server startup, and release-facing diagnostics.

Main parts

  • launcher.ts
  • launcher_paths.ts
  • startup_args.ts
  • runtime_config.ts

Python selection

Explicit interpreter, project .venv, active virtualenv or Conda, then a new project .venv. A separate managed starter environment is optional.

Does not own

Document semantics or execution. Headless run and validate are delegated to python -m rowcall.

Drill down: installed launch sequence
  1. Resolve a folder to its graph.py, or accept a specific .py file.
  2. Select or create a compatible Python environment.
  3. Materialize the bundled UI and Python package under ~/.rowcall/bundled.
  4. Create a random token and start a child __server process.
  5. Wait for readiness, then open the tokenized local URL.

02

Browser Workspace

One React screen for one document. It shows the graph, accepts edits, coordinates saves, and presents live run state.

Owns: unsaved intent and presentation state. It does not own the authoritative Python source or graph semantics.

Workspace Coordinator

App.tsx connects document load, edit, save, disk polling, selection, canvas, inspector, and execution.

Document Session

An in-memory editable document, the loaded base revision, a coalesced operation queue, and save/reload state.

Run Session

useExecutionSession tracks the plan, per-step state, final results, freshness, notifications, and result-store identity.

Drill down: canvas and inspector

Graph Canvas is a React Flow projection. It shows step cards and connections and reports gestures upward. Inspector contains Develop, Overview, and Results views. It edits code and declared values, and it renders previews and diagnostics.

The browser keeps three related shapes: the editable document, a derived runtime graph, and a React Flow rendering graph. The Python file is still the authority.

Source trail: App.tsx:130, Canvas.tsx:108, InspectorPanel.tsx:3281, useExecutionSession.ts:22
03

Local App Server

A Deno/Hono server that binds the browser to one local document and one selected Python environment.

Owns: static files, local-request security, HTTP contracts, revision-bound source reads, SSE framing, and coordination between browser, disk, and Python.

Document Coordinator

python_document.ts serializes document access, locks and recovers files, calls short-lived workers, checks revisions, and commits source plus sidecar.

Python Worker Bridge

PythonWorkerClient starts Python, sends NDJSON commands one at a time, reads events, and kills the process group on cancellation.

Single-instance state

The active document path, UI directory, security context, status cache, document queue, and shared execution worker are module-level state.

Drill down: request boundaries
  • GET /document loads the current document.
  • GET /document/status reports source/sidecar freshness and validity.
  • POST /document/operations applies a revision-bound edit batch.
  • POST /run-to-node and POST /run-graph execute a checked source revision.
  • POST /results/table pages or sorts the latest retained table.

The browser requests Server-Sent Events for runs. The server converts Python worker events to SSE and sends a heartbeat while Python is busy.

Source trail: main.ts:674, :713, :753, :899, :1008
04

Python Core

The semantic center. Both the visual app and the headless CLI converge here.

Owns: the accepted Python grammar, document validation, source rewriting, graph planning, execution, value copying, previews, and interactive result inspection.

Document Engine

rowcall/document/ parses the AST without executing user code, validates the graph, applies semantic rewrites, and builds plans.

Execution Engine

Evaluates document globals once, runs planned steps sequentially in new namespaces, stops at the first failure, and captures bounded diagnostics.

Preview Engine

Leaves rich values in Python. It sends only safe JSON, table, text, repr, and declared PNG previews to the browser.

Drill down: workers and result state

Document inspection and rewrite calls use a new Python process for each operation. Execution uses one long-lived Runtime Worker. The long-lived process lets Rowcall retain raw Pandas or Polars outputs for later table paging.

The worker retains raw outputs for only the latest successful app run. A later successful run replaces them. Cancellation kills the worker, which also clears them.

Source trail: worker.py:14, session.py:18, executor.py:70, previews.py:16
05

Document Files

Two local files form the durable editor document. Only one is required to run.

Owns: durable user work. The Python source is canonical for computation; the sidecar is optional and non-executable.

Python document

Imports, globals, decorated functions, declared outputs and views, return dictionaries, and depends_on calls.

Sidecar

A sibling .rowcall.json with node IDs, canvas positions, descriptions, and a currently transported title field.

App Revision

A SHA-256 value derived from the source revision and normalized sidecar. Both kinds of edit participate in conflict detection.

Drill down: safe two-file saves

The Document Coordinator uses a lock, temporary files, directory sync, alias checks, and a small transaction journal. If a save is interrupted between the Python and sidecar commits, the next read can recover or report a safe failure.

This is one of the most complex areas in the repository. It protects the user’s source file, so the companion audit recommends keeping its behavior for beta.

04 / DOCUMENT

The graph is normal Python with a strict shape.

The restrictions make a visual editor possible. Rowcall can find and rewrite graph structure without importing or executing the document.

from rowcall import node

@node(id="n_load", outputs=["orders"])
def load_orders():
    orders = read_orders("orders.csv")
    return {"orders": orders}

@node(
    id="n_summary",
    outputs=["summary"],
    views=["chart"],
)
def summarize_orders(orders):
    summary = orders.group_by("region").sum()
    chart = make_chart(summary)
    return {"summary": summary, "chart": chart}

summarize_orders.depends_on(load_orders)
Stable node IDn_summary anchors edges and sidecar metadata even if the function name changes.
Whole-node edgeEvery declared output from load_orders becomes a direct input candidate for summarize_orders.
Parameters are the input contractThe downstream parameter names must exactly match the combined direct upstream outputs.
Outputs flowsummary can become a downstream input and is also previewed.
Views do not flowchart is for a person to inspect. It does not become a downstream input.
Strict returnThe final dictionary must contain the ordered union of declared outputs and views.
Important limitation: a node gets a fresh dictionary namespace, but all nodes in a run share one Python process. Rowcall copies upstream values when it can. If copying a custom value fails, the current runtime passes it by reference with a warning. That can let mutation cross branches.

What happens inside a fresh run

  1. Invalidate local importsTry to observe edits to helper modules.
  2. Parse ASTDiscover steps, declarations, source ranges, and edges.
  3. Validate graphReject cycles, missing steps, name conflicts, and bad parameters.
  4. Build planTopologically order the required dependency subgraph.
  5. Run globalsEvaluate non-node top-level code once.
  6. Run stepsCopy inputs, execute each namespace, stop on failure.
  7. Publish previewsKeep rich values in Python; send bounded evidence.

05 / STATE

Where state lives, and when it disappears.

There is no single store. The system deliberately uses files for durable work and memory for editing and inspection.

State Owner and location Lifetime What replaces it
Computation and graph Python document on disk Durable A successful save or an external file edit
Canvas metadata Sibling .rowcall.json Durable, optional A metadata save; deleting it loses layout, not computation
Unsaved document React memory in the Document Session Browser memory Save response, reload, browser close, or crash
Pending operations Browser queue; Deno serializes active file work Until save settles Successful save, definite rejection, or guarded reload
Run presentation Run Session and TanStack Query Browser memory New run, edit freshness change, reload, or close
Raw Python results Latest Result Store in the Runtime Worker Worker lifetime Later successful run, cancellation, or process exit
Project packages Project .venv Project lifetime Environment repair or deletion
Managed starter packages ~/.rowcall/venvs/default Launcher-managed Version refresh or reset-env
Freshness

“Fresh” has two meanings

A document is fresh when source plus sidecar match the loaded App Revision. A result is fresh when it was produced from the current source value.

No cache

Results do not skip computation

The Latest Result Store exists only for inspection. Running again still rebuilds the full required plan.

Failure

Unknown save outcome is conservative

If the browser cannot know whether a save committed, it blocks further edit/save/run actions until reload. It does not replay the operation batch.

06 / TRUST

Protected local app; fully trusted Python.

The web boundary has safeguards. The Python boundary intentionally does not: opening a document means trusting its code.

Local web boundary

  • Default bind is loopback.
  • Host and Origin headers are checked.
  • Document and run routes require a random session token.
  • The first URL carries the token; the browser stores it and removes it from the visible URL.
  • The active document path is fixed at server startup.
trust boundary

Python execution boundary

  • User Python runs with the launching user’s permissions.
  • It can read/write files, use the network, start processes, and import native packages.
  • There is no sandbox, time limit, or memory limit.
  • Namespace isolation is not process isolation.
  • Only trusted documents are appropriate for this beta.
Current-state caveat: API authentication is based on a list of known route prefixes, and the token-bearing server URL is written to the launcher log. The companion audit recommends a simpler fail-closed rule and token redaction.

Output is bounded

Per-step stdout and stderr retain up to 1 MiB each. repr, JSON, table, warning, and image previews have separate limits.

Cancellation is forceful

Aborting a streamed run terminates the Python worker process group. A later request starts a replacement worker.

Distribution is beta-grade

The installer verifies SHA-256 checksums, but the macOS launcher is unsigned and not notarized. Publishing is manual.
